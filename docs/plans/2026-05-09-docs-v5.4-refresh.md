# Documentation Refresh v5.4

## 1. Goal

Create a current v5.4 markdown specification set in `docs/` that reflects the implemented system behavior after the Office refactor, expanded System Management coverage, guarded deletes, live inquiry/reporting, and Pricing Model support.

## 2. Scope

In scope:
- create current v5.4 markdown specs for functional behavior, UI, API, authorization, business rules, use cases, NFRs, and data-model references
- mark the older v5.2 markdown deltas as superseded
- refresh the schema diagram timestamp and current-state notes

Out of scope:
- editing legacy `.docx` files
- changing application behavior

## 3. Inputs

- existing `docs/*.md`
- current Django models, routes, policies, and services
- completed plan files in `docs/plans/`
- `AGENTS.md`

## 4. Risks

- documentation could drift from implementation if it copies old assumptions instead of current code
- API documentation must distinguish between server-rendered UI capabilities and JSON API capabilities

## 5. Deliverables

- `docs/specification-index-v5.4.md`
- `docs/functional-spec-v5.4.md`
- `docs/ui-screen-spec-v5.4.md`
- `docs/integration-api-spec-v5.4.md`
- `docs/authorization-matrix-v5.4.md`
- `docs/business-rules-catalog-v5.4.md`
- `docs/use-cases-acceptance-v5.4.md`
- `docs/non-functional-requirements-v5.4.md`
- `docs/data-model-erd-v5.4.md`
